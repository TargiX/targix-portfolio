## The pitch

Most habit and mood apps are a wall of inputs. Anchor is the opposite: two short rituals — one to open the day, one to close it — and a quiet trend line in between. Set an intention in the morning, log how you slept, breathe. Reflect and journal at night, prep tomorrow's sleep window. That's the whole product.

It started as a prototype to answer a narrower question: **how far can one Next.js codebase stretch across web, mobile, and desktop without forking the UI?** The answer turned out to be "all the way," and that's the part worth showing.

## One codebase, three targets

The app is a standard Next.js 16 App Router project. The trick is that every route is client-rendered against local state (no SSR data dependency), which means the exact same build can run three ways:

- **Web** — deployed on Vercel, server build, the default.
- **Mobile** — `BUILD_TARGET=native next build` flips on `output: "export"`, producing a static bundle that **Capacitor** wraps into native iOS and Android shells.
- **Desktop** — the same static bundle, wrapped by `@capacitor-community/electron` for macOS / Windows / Linux.

The conditional in `next.config.mjs` is the whole seam:

```js
const isNativeBuild = process.env.BUILD_TARGET === "native";

const nextConfig = {
  ...(isNativeBuild && {
    output: "export",
    images: { unoptimized: true },
    trailingSlash: true,
  }),
};
```

Vercel keeps the full server build; `npm run cap:sync` produces the static export and copies it into the native projects. No second UI, no React Native rewrite, no divergent component tree.

## Stack decisions worth defending

**Next.js for an app that's mostly client-side.** The product is a stateful flow, not a content site — but App Router's file routing, font handling, and the static-export escape hatch make it the path of least resistance to a Capacitor bundle. Server components would have been dead weight here, so there are none.

**Radix primitives + Tailwind v4, not a component kit.** The whole thing is warm, paper-and-ink, with a custom OKLCH palette. Radix gives accessible behavior (slider, dialog, tabs) and I style it down to the token. shadcn-style ownership of the component source meant I could fix things directly instead of fighting a library's defaults.

**Framer Motion, used sparingly.** Ritual steps cross-fade, the brand motif settles in, status cards slide. Animation is the difference between "prototype" and "product," but every extra spring is a frame budget — so it's restrained on purpose.

## What AI got wrong (and how I caught it)

I built this fast with an AI assistant, which is exactly where critical review earns its keep. The clearest example: the sleep slider rendered as an invisible track — only the thumb showed, floating on white.

The generated Tailwind looked plausible:

```tsx
<SliderPrimitive.Track
  className="... data-horizontal:h-2 ..." />
```

But Radix sets `data-orientation="horizontal"`, not `data-horizontal`. So `data-horizontal:h-2` matched nothing, the track collapsed to `height: 0`, and the rail vanished. A color tweak would never have fixed it — the element had no height at all. The actual fix was the selector:

```tsx
className="... data-[orientation=horizontal]:h-2 ..."
```

That's the recurring tax on AI-generated frontend: it's confident with modern APIs and quietly wrong at the edges. Reading the rendered DOM, not the source, is what surfaced it.

## What I'd do differently

- **Persist state to IndexedDB from day one.** The prototype keeps entries in memory; a real release needs offline-first storage that survives a reload, which Capacitor makes easy but I deferred.
- **Wire Sentry before shipping, not after.** Cross-platform means cross-platform bugs; I'd want the crash data from the first native build.
- **Lock the design tokens earlier.** I iterated the palette in the components and had to reconcile it back into CSS variables. Tokens first, components second.

## Numbers

- **Targets from one codebase:** 3 — web, mobile (iOS + Android), desktop.
- **Production build:** 7 static routes, clean typecheck + lint.
- **Native seam:** one env-gated config block, no UI fork.
- **Time to cross-platform prototype:** a single focused build session.
